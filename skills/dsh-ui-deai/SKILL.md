# dsh-ui-deai

把“看起来像模板”转化为具体、可核对的界面问题。保持用户的产品用途和明确的品牌选择，把每项调整与页面任务联系起来。

## 接入宿主

- `ui_deai_audit`：扫描文件或目录，输出位置、规则提示与静态分数。指定与当前页面相关的最小路径，避免把依赖或其他页面算进来。
- `ui_deai_direction`：记录 `product`、`audience`、`task`、`keep`、`changes`、`acceptance`。没有证据的内容保持待明确，不根据项目名称猜测品牌风格。
- `ui_deai_pass`：更新分类的处理状态，并用 note 记录修改或保留理由。
- `ui_deai_snapshot`：从 URL 保存静态 HTML 与截图；用 `phase: before` 或 `after` 区分用途。
- `ui_deai_story`：把阶段清单中已有的页面制成视频。只在用户需要演示时使用，清单格式见 [capture.md]({{SKILL_DIR}}/references/capture.md)。

浮动面板和设置页均显示为 `dsh-ui-deai`，命令为 `/dsh-ui-deai [源码路径]`。

## 审查与调整

先确认页面的主要任务和用户希望改变的范围。已有明确指令时直接执行；缺少会改变方案的产品信息时再询问。扫描提示并不等同于错误：结合实际截图、相邻组件和交互过程决定是否处理。

将工作归入六个分类，按问题影响选择先后顺序：

| 分类 id | 观察对象 |
| --- | --- |
| content | 内容是否帮助用户理解和完成任务，宣称是否有依据 |
| hierarchy | 首要信息、操作和次要信息是否容易区分 |
| consistency | 同类组件是否共享有意设计的规则 |
| interaction | 操作反馈、加载、错误、空状态是否明确 |
| accessibility | 键盘路径、可读名称、缩放和窄屏阅读 |
| decoration | 图形与特效是否服务于信息或已确认的品牌 |

不预设某种颜色、字体或装饰必然错误。针对真实问题调整，并在 note 中记录合理保留的例外。具体复核方式见 [review.md]({{SKILL_DIR}}/references/review.md)。

如果需要改代码，先记录当前界面的约束与验收条件，按影响最大的部分推进。完成后重新扫描同一目标，并实际检查关键任务、窄屏布局与焦点。分数上升只是静态提示减少，不证明设计工作完成；未触发规则也不应成为强行改动页面的理由。

报告应说明修改了什么、为什么、检查结果，以及仍需用户确认的产品信息。截图输出是静态参考，不能当成原应用的完整可交互副本。
