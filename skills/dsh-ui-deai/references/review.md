# 审查依据

## 从任务而不是装饰开始

描述用户来到当前页面要做的事情，再找出界面中阻碍这件事的部分。例如信息查找困难可能来自排序、重复文案或缺失状态，不一定需要换配色。把观察到的现象与推测分开记录。

## 处理扫描提示

每项提示至少核对一次实际上下文：

- 字重或间距种类较多：这些差异是否对应明确的组件角色？孤立的像素值不足以证明不一致。
- 渐变文字、阴影或动画：是否存在品牌依据、阅读障碍、注意力竞争或性能问题？特效本身不是错误。
- 输入名称或图标按钮：检查组件是否通过属性传递标签，避免仅凭源码片段下结论。
- 文案泛化：把缺乏信息的承诺改成用户能够判断的事实。没有依据的数字不要补写。

扫描器采用文本启发式，不解析完整组件树，不计算对比度，也不证明符合任何可访问性标准。跨组件标签、动态样式和运行时内容需要人工检查。

## 记录验收

根据任务选择少量可操作的条件：用户能找到主要操作；提交后有明确反馈；错误发生时能恢复；键盘可以到达关键控件；目标屏幕宽度下无需阅读横向溢出的正文。视觉比较使用同一数据、同一视口和同一主题。

类别完成表示该类问题已经复核。合理保留的设计也可以完成，但应写明原因。不要为了把分数刷到 100 而损害产品。
